# Audit, 2026-10-12

Everything built so far, read end to end: kernel, control-room server, UI (desktop and phone),
the Google and web tools, the four agents, the docs and site, the Android and iPhone wrappers,
CI and the repo itself. Each item says what is wrong, why it matters, and the fix. Severity:
**bug** (does the wrong thing), **security** (lets something through), **gap** (missing
guard or test), **stale** (docs say something untrue), **polish**.

Checked and found clean: no secrets, tokens or personal data in the tracked files (one
exception, item S8); the Gmail tool has no path to send, delete, trash or unlabel; the policy
engine does what the docs promise (first match wins, nothing matching is ask, always-blocked
tools are hidden from the model); the sign-in code is careful (constant-time compare, 0600
token file, HttpOnly cookie, Host check); the app works unpaired and offline; approvals can't
double-fire; no ISO times, UTC or orange anywhere in the UI.

## A. The "always-on" promise (kernel, scheduler)

**Done 2026-10-12**, all of it (A9–A12 with batch 6).

These are why this morning's 7:00 brief and 7:15 inbox sort never happened on their own.

- **A1 · bug · a run that dies offline counts as done.** Overnight the Mac, lid closed, woke
  in the dark for a few seconds every ~10 minutes. The scheduler fired the due runs in those
  seconds; the model call failed ("fetch failed", no network); the run was recorded as an error.
  At the real wake (9:20) the scheduler saw a run had already started at 7:04 and skipped the
  7:00 catch-up. `scheduler.ts:144-147` decides "due" from the newest cron/catch-up run's
  *start time* whatever its status (`ui-server.ts:171-174`, `index.ts:186-189`); the Gemini
  provider has no retry for connection errors and no timeout (`providers/gemini.ts:122`), so a
  request cut by sleep hung until the next wake (the "1000-7000 s" runs).
  Fix (three small pieces): mark a run that failed before its first model turn as `offline`
  in `run.end` (additive, the recorder format stays compatible) and skip such runs when
  looking for the last run; before a catch-up, do a 3 s DNS lookup of the provider host and
  wait if it fails (dark wakes then cost nothing); give provider calls a 2-minute timeout.
- **A2 · bug · a queued catch-up fires after the agent's real run already did** (reproduced
  with a script): `scheduler.ts:150-153`. Re-check "still due?" inside the `.then` before firing.
- **A3 · bug · a run started from the control room or chat isn't seen by the scheduler**
  (`ui-server.ts:96,165-168` vs `scheduler.ts:163`): a cron fire during a chat run starts a
  second Bea on the same threads. Give the scheduler an `isBusy(name)` hook.
- **A4 · bug · "Run now" on a Garufile with an unknown provider or a budget on an unpriced
  model crashes the whole service** (unhandled rejection, `ui-server.ts:323`); launchd restarts
  it 5 s later, interrupting every other run. Add the `.catch` the chat route already has.
- **A5 · bug · `service status` says "running" whenever the service is *loaded*, even when
  the process is down** (`index.ts:323`). Also the plist bakes in Homebrew's versioned node
  path, so `brew upgrade node` breaks the service silently. Parse `state = running`; use
  `/opt/homebrew/opt/node/bin/node`.
- **A6 · gap · a bad pattern in a rule is only discovered when the tool is first called**
  (`garufile.ts:26`): the run dies with "Invalid regular expression" while `garu validate`
  said fine. This is this morning's Node 22 incident in general form. Compile `matches` at
  parse time.
- **A7 · bug · the "budget on an unpriced model" check runs after `run.start` is written and
  outside the try** (`agent.ts:80-84`): every scheduled fire leaves a ghost "running" run that
  turns "interrupted" after 10 min. Move the check above the recorder.
- **A8 · gap · cost accrues only when the provider reports usage** (`agent.ts:126-133`);
  Gemini sometimes doesn't, and then the cap never trips but `priced: true` is still claimed.
  Record `priced: false` in that case.
- **A9 · gap · a tool server's stderr is piped and never read** (`bus.ts:114`): a server that
  logs more than ~16 KB to stderr (Python ones do) blocks, and every later call times out at
  60 s. Drain it, keep the last few KB for the "failed to start" message.
- **A10 · gap · `stop()` has no deadline and a paused approval can't be cancelled**
  (`scheduler.ts:178-187`, `inbox.ts:84-95`): `service restart` either waits up to 30 min or
  gets killed, leaving an orphan ask. Add a deadline and resolve the wait as declined
  "garu stopped".
- **A11 · gap · 6-character ids are written without an existence check and the inbox is
  never pruned** (`inbox.ts:65-78`, `grants.ts:78`). Regenerate on collision.
- **A12 · polish** · `sandbox.ts:47-49` puts Garufile `env` secrets on docker's command line
  (visible in `ps`); pass them by name like Garu's own token. `maxCostUsd: 0` with free pricing
  stops every run after turn 1 (`agent.ts:150`, `>=`). Server names may contain `__` although
  the tool-name mapping assumes they don't (`garufile.ts:47`, `provider.ts:69`).

## S. Security

**Done 2026-10-12**, all of it. S4 also made `matches` on a list check every entry, so Bea's rule
says `to`, not `to.0`. S6 returns `secret: true` to the card; the card's own line for it is U-work.

- **S1 · security · any web page served from localhost can read the sign-in token.** The
  control room trusts requests from the Mac itself without a token (`ui-auth.ts:90`) and
  echoes CORS for `http://localhost:<any port>` (`:124`), so a page on any local dev server,
  notebook or docs preview can `fetch("http://localhost:4000/api/pair")`, get the token, and
  then approve, run and chat as you. A compromised npm package in any other project crosses
  that line. Fix: in `authenticate`, treat a request whose `Origin` is present and not equal
  to its own `Host` as not-direct; make `/api/pair` require a cookie or bearer.
- **S2 · security · the web-fetch tool follows redirects anywhere, including the Mac itself.**
  `mcp-fetch/tools.ts:71-81` checks only the scheme. An allowed outside host that redirects to
  `http://127.0.0.1:4000/api/pair` returns the token to the model (with S1's loopback trust).
  Today's rules don't allow it (Rook reaches api.github.com only); a widened rule would.
  Fix: follow redirects by hand and refuse loopback, link-local and private addresses at every
  hop; refuse an `http://` webhook for `post_message` (`:128`).
- **S3 · security · "Add to Garufile" puts the learned `allow` above a `block` for the same
  tool** (`suggest.ts:125-128`): it inserts before the *first* matching rule whatever its
  action. On Bea's file the next accepted suggestion would land above the no-reply block and
  override it. Fix: insert before the first matching `ask` and after any `block`; warn in the
  card when a block would be shadowed. Related: `garu validate` doesn't flag a rule shadowed by
  an earlier unconditional one (`policy.ts:125-135`), though the README says it does.
- **S4 · security · a rule condition looks at one list entry only.** `to.0` (Bea's block) is
  evaded by a second recipient: `to: ["ok@x.com", "noreply@x.com"]`; a string `to` is indexed
  by character. Fix: when the value is a list, `matches` tests every entry; Bea's rule then
  says `to`, not `to.0`. (The Gmail tool itself already refuses, so nothing gets through
  today; the policy should still be right on its own.)
- **S5 · security · path conditions match the raw string** (`suggest.ts:76-78`, the shipped
  suffix rules): `workspace/notes/../../.garu/x` satisfies a `^workspace/notes/` rule.
  Containment is left to the fs server's own root check. Normalize before matching; treat a
  surviving `..` as no match.
- **S6 · security · the diff preview reads any file under the project root named by the
  agent**, including `.env` and `.garu/ui-token` (`ui-server.ts:384-394`): an injected "write
  .env" request would show the secrets on the review card, phone included, before anyone
  decides. Refuse `.env*` and `.garu/**`; resolve real paths.
- **S7 · security · tool-server error messages include the expanded arguments** (`bus.ts:143`):
  the first Garufile that passes `--token ${X}` in `args` leaks it into the recorder on a
  startup failure. Build messages from the unexpanded spec.
- **S8 · security · your Mac's real Tailscale address is committed in a test file**
  (`packages/cli/src/ui-addresses.test.ts`, 7 times, on GitHub), against our own rule. Replace
  with the placeholder the docs use.
- **S9 · security · the Android app backs up its data to Google Drive**
  (`AndroidManifest.xml:4`, `allowBackup="true"`): the pairing token lives in the web view's
  storage, so "nothing in the cloud" isn't true. Set `allowBackup="false"`.
- **S10 · security · the release keystore isn't ignored** (`android/.gitignore:57-58`
  commented out; `keystore.properties` not ignored). With `git add -A` it's one commit from
  GitHub. Uncomment; add `keystore.properties`, `*.p12`, `*.mobileprovision`.
- **S11 · bug · `npm run demo-data` from the repo root seeds fake runs, a fake pending draft
  and a real-looking 14-hour grant into the live `.garu/`** (`scripts/demo-data.mjs:16`,
  `package.json:19`). Refuse when `.garu/ui-token` exists unless `--force`.
- **S12 · security (low)** · `seen.note` records forwarded headers before authentication
  (`ui-server.ts:257`), so an unauthenticated request can plant an address in the pairing
  list. Note after auth. · `readBody` has no size cap and runs for `/api/login` before any
  check (`:555-565`). Cap at 1 MB. · `/api/runs?agent=` isn't character-checked (`:358`), so
  `../` lists any `.jsonl` on the machine (authenticated only). · `?token=` is honoured on every
  GET, not just `/api/events` (`ui-auth.ts:69,88`), so it can land in logs.
